# Breaking: Tunnel relays can only dial public addresses; wake proxies are isolated per server; sidecar ports and account overrides are refused

Outside `networkPolicies.tenantIsolation`, a tunnel relay now reaches its provider (frp, Tailscale, playit) on public addresses only, and reaches its advertised ports on its own game server only. A frp server set by IP address keeps working. Before upgrading, add a LAN frp server reached by hostname to `networkPolicies.tunnelEgress.allowCIDRs` (for example `192.168.1.20/32`). A template can no longer advertise TCP 8090, 9090 or 9091, the agent and capture ports. A server's `spec.serviceAccountName` can no longer name another component's or another server's ServiceAccount, or a Helm-managed one. The new `operator.allowedImageRegistries` setting can limit `spec.image` overrides to chosen registries. Every server whose template advertises a port now gets per-server wake proxy isolation by default (what `sentinelIsolation: true` used to opt into): its sleeping-server proxy can reach only its own server's advertised ports. Running game servers take this at their next start, so the upgrade restarts no game; wake proxies and playit tunnel pods restart once.
