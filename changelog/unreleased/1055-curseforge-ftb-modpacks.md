# CurseForge and FTB modpacks with pinned versions

The server's Modpacks tab can now install, pin and remove modpacks from Modrinth, CurseForge and Feed The Beast (FTB), each pinned to a chosen version so a restart never upgrades a pack by surprise. The operator applies a pack recorded in the new `GameServer.spec.modpack` field, with an optional backup first; removing a pack empties the mods folder and keeps the world. Packs with files CurseForge blocks from automatic download are listed with links and the `downloads/` path to upload them to. Servers already running an unpinned Modrinth pack are pinned to their installed version at the next quiet moment (no players online), with one restart. Admins can switch on sharing the CurseForge key with servers on images without a built-in key in Admin settings, under Mod registries; see [the residual risk](../../docs/security.md#sharing-the-curseforge-key-with-game-servers). Turning sharing on or off reaches a running server when it has no players online (or is stopped or asleep), because the change restarts its pod. Module authors get new template fields and the `ftb` provider, see [Modpacks](../../docs/module-authoring.md).

API change: `POST /servers/{name}/modpack` now answers `202 Accepted` with the modpack view (phase `Pending`) instead of `200 {"ok":true}`, and answers `409` while a previous change is still in progress. [PR #1055](https://github.com/GameplanePanel/Gameplane/pull/1055)
