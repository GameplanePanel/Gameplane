# Backup retention only prunes its own, restorable backups

A backup schedule now prunes only backups it can prove it created for the server that exists now, so deleting a server or schedule and creating a new one with the same name no longer deletes the old one's snapshots. Retention also ignores a backup that finished but has no snapshot ID yet, so it can no longer push out your last restorable snapshot, and the dashboard shows such a backup as "Awaiting snapshot ID". Backups made before this upgrade are no longer pruned automatically: see [Scheduled backup retention and provenance](../../docs/operator-operations.md#scheduled-backup-retention-and-provenance) to check and retire them. Fixes #960 and #961.
