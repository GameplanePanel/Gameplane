# i18n — Specification

**Status:** pre-v1 (spec 019)
**Module / package:** `github.com/GameplanePanel/gameplane/i18n`
**Dependencies:** stdlib, `golang.org/x/text` and `gopkg.in/yaml.v3` (the `i18n-check --module` mode reads module manifests; Go 1.26+)

## Purpose

Shared language packs for the dashboard, the API, the operator and the module tooling. One module owns the English reference catalog, the translated packs, the ICU message formatter, the pack validator and the `i18n-check` CI command, so every consumer reads the same messages and the same rules decide which translations ship.

The feature's design is in [`../specs/019-localization-language-packs/spec.md`](../specs/019-localization-language-packs/spec.md).

## Responsibilities

1. Hold the English reference catalog `locales/en/app.json` and the translated packs `locales/<tag>/app.json` with their `meta.json`, embedded at build time.
2. Parse and format the ICU MessageFormat subset (`icu`): arguments, number, date and time, plural, select, tags and apostrophe quoting.
3. Parse, marshal and hash pack files, and define the pack metadata (`pack`).
4. Validate the reference, metadata and translations, and compute completeness and listing status (`pack`).
5. Load the embedded packs and look messages up with a regional, base-language and reference fallback (`catalog`).
6. Run the CI checks, sync the server-side registry, stamp source hashes and write the language manifest and the summary (`cmd/i18n-check`).

## Non-goals / boundaries

- Does **not** translate text. Translations are produced and reviewed outside the code.
- Does **not** render a page, a notification or a console line. Consumers call `catalog.Lookup` and decide where the text goes.
- Does **not** talk to the network. The server registry arrives as a file passed to `i18n-check`.
- Does **not** store per-user language choices. The API and the dashboard own those.
- Does **not** accept HTML. Translations may use only the `<b>` and `<link>` tags, and no HTML entities or script links.

## Directory & package layout

```
i18n/
├── doc.go              # package comment
├── embed.go            # go:embed locales/*/*.json → Locales (root package: embed paths cannot use "..")
├── locales/
│   ├── en/app.json     # reference catalog; GENERATED by i18n-check tooling, never hand-edited
│   ├── en/meta.json    # reference metadata (tag, nativeName, englishName, direction)
│   └── <tag>/…         # translated packs
├── icu/                # parse.go, placeholders.go, format.go: ICU subset
├── pack/               # pack.go (types, parse, marshal, hash, tags), validate.go, completeness.go, stamp.go
├── modlocale/          # ids.go: module id derivation (Derive, ValidID) shared by gp-module, i18n-check --module and the operator
├── catalog/            # catalog.go: Load, Default, lookup chain, listing
├── cmd/i18n-check/     # main.go: CLI, app mode and module mode (--module: en.json must equal the ids derived from template.yaml + module.yaml; --stamp is app-mode only)
├── testdata/defective/ # one fixture per finding code (SC-007)
├── .testcoverage.yml   # 90% coverage gate
└── go.mod
```

## Consumers

- **web** — build-time import of `locales/` (through the pack files) so the dashboard ships only the messages it uses.
- **api** — notification text and language validation (`catalog.IsListed`, `catalog.Tags`).
- **operator** — module locales and the language a module reports.
- **gp-module** — validates module locales with the same pack rules.
- **module-repo CI** — runs `i18n-check` in module mode against each module's flat `en.json` and `<tag>.json` files.

## Invariants

1. The reference `locales/en/app.json` is generated and never hand-edited. Changes come from the extraction or server-sync step of `i18n-check`.
2. `ListingThreshold` is 80: a language is listed only at 80% completeness or more, is left-to-right, and is not the `en-XA` pseudo-locale. The reference is always listed.
3. Invalid translations are never shown. A translation that fails to parse, changes placeholders or uses disallowed markup is dropped before `catalog` sees it, and lookup falls back to the next pack or to English.
4. A translation whose English source changed since it was translated is still shown, but reported as `needs-review`.

## Pack format and check tool

The pack format and the `i18n-check` behaviour are defined by the binding contracts [`pack-format.md`](../specs/019-localization-language-packs/contracts/pack-format.md) and [`check-tool.md`](../specs/019-localization-language-packs/contracts/check-tool.md). One addition to `check-tool.md`: `--sync-server` and `--check-server` read the API message registry from `--registry <file>` (the JSON array written by `api/cmd/messages-export`).
