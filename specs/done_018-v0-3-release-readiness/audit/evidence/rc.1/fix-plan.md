## Fix groups (in order)

Ordered S1 → S4; within a severity, core paths come first in this order: install/upgrade, auth, game-server lifecycle, backup/restore, console. Other code groups follow, and docs-only groups come last. A group that absorbs a lower-severity twin (same files, same root cause) sits at its highest finding's severity, and the lower severity is shown next to the twin's ID. Branch names are proposals for T055's fan-out. T055 names branches `fix/018-F-NNN` (one per finding) while T050 asks for one branch per group; the names below follow T050, and T054/T063 keep the branch names those tasks set. The naming conflict is raised with OD-024. `type:`/`area:` labels per CLAUDE.md rule 14. "specs.md?" = does the owning component's `specs.md` need an update alongside the code (CLAUDE.md common workflow / T055). "design.pen?" = does a web UI change need a Pencil pass first (CLAUDE.md rule 1) before any React edit.

Regression-test conventions used below:
- Go E2E cases name a real bucket in `test/e2e/buckets.sh`. New cases in `api-*` buckets must fit that bucket's admin-login budget (about 7 per job, per the `buckets.sh` header; `api-roles` is already there, see F-042); prefer extending an existing test. `bot-heavy` never runs in CI, so it cannot carry a regression.
- The dashboard is not driven by any `buckets.sh` bucket. Web fixes use the Playwright suites instead: `web/e2e/specs/*.spec.ts` (CI job `web e2e (mock)`; mock specs pick MSW handler variants by cookie, because `page.route()` does not intercept under MSW, see F-004) or `web/e2e/specs/live/*.spec.ts` (job `e2e web live`, which reaches the API through the Vite proxy, not the web pod's nginx).
- Chart fixes can add render assertions to the `chart render` job in `.github/workflows/ci.yaml`.
- Any new or changed test, fixture or CI check needs the maintainer's sign-off first (CLAUDE.md override 1).
- Live re-verification (T058) of some groups depends on pending OD-021 items; the Dependencies column names them.
