**Ground truth**: every task below is written against the shipped CRD schema (`modules/.schema/gametemplate.schema.json`) and the real `modules/` submodule contents. Where `contracts/gametemplate-contract.md` and `data-model.md` previously disagreed with the schema, the maintainer has ruled on every disagreement: T006-T010 correct those artifacts directly (no more "requires maintainer sign-off" deferral — the ruling IS the sign-off), and T005 records the handful of questions that remain genuinely open in a new `specs/015-top-steam-game-modules/OPEN-DECISIONS.md`. The schema's field description states `capabilities.lifecycle.stop` requires `rcon.protocol != none`, but the apiserver does not enforce that as a CEL rule and `modules/dont-starve-together/template.yaml` ships a `stop` sequence under `rcon.protocol: none` + `consoleMode: pty` — this ambiguity is NOT resolved by any maintainer ruling and stays recorded in `OPEN-DECISIONS.md` (T005); see T064.

**Tests**: Included — mandatory per spec.md's User Story acceptance scenarios, FR-011, and Constitution Principle I (E2E-Tested Delivery). Every module gets a real wire-protocol e2e probe in `test/e2e/`; resource-heavy games (>8 GB RAM) get their test committed with an explicit CI-exclusion comment in `test/e2e/buckets.sh`, per the existing `bucket_bot_heavy` pattern — never a silent skip. Every new game additionally gets a `test/e2e/internal/<game>/` probe package (Phase 2) proven to fail against a dead address and succeed against a real listener before any test task is allowed to depend on it, per Constitution Principle I. The two new agent-side RCON clients (`rest.go`, `cli.go` — T018/T019) each need real Go unit tests of their own: `agent/.testcoverage.yml` gates the `agent` module at 90%, and these are new files with no coverage yet. The fail-dead/succeed-live proof is a `go run ./test/e2e/internal/<game>` invocation (a build-and-run, not a test suite) or a CI e2e-bucket run; the Go unit tests for T018/T019 are authored locally and verified only by the CI run in T123 — never by a local `go test` (rule 8).

**Local execution**: Per CLAUDE.md rule 8, `make test`, `make lint`, `make cover`, `go test`, and `npm test` MUST NOT be run locally — GitHub Actions is the source of truth. `python3 modules/validate.py` in its default (non-`--pin`) mode is sanctioned (plan.md: "local execution limited to standard static preflight checks"); T120 uses it, `--pin` mode (T119) rewrites templates and is used only there. CLAUDE.md rule 7 additionally requires `make generate` and `make manifests` to run locally in the same commit as any CRD Go type edit (T016), and `make module-schema` (T017) is the codegen step that keeps the module schema in sync — none of these three are test/lint suites, so running them locally is required, not merely permitted.

**Organization**: Tasks are grouped by user story (US1-US5, priorities from spec.md: US1 P1, US2 P1, US3 P2, US4 P2, US5 P3) so each story is independently deliverable. Because every story after US1 edits the same per-module `template.yaml` files US1 authors, US2-US5 run *after* US1 completes rather than concurrently with it (see Dependencies below) — they remain independently testable, just not independently schedulable against a not-yet-authored file. Phase 2 (Foundational) is now substantially larger than a typical feature's setup phase: besides the per-module prep work, it implements two new `rcon.protocol` values end-to-end (CRD → codegen → agent → validator) and builds four Gameplane-owned container images, so it touches `operator/`, `agent/`, `charts/`, and `web/` in addition to `modules/`, `specs/`, and `test/e2e/`.
