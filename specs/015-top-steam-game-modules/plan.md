# Implementation Plan: Dedicated Server Modules for Top Steam Games

**Branch**: `015-top-steam-game-modules` | **Date**: 2026-09-03 (refreshed 2026-10-09 to match shipped scope) | **Spec**: [./spec.md](./spec.md)

**Input**: Feature specification from `specs/015-top-steam-game-modules/spec.md`

## Summary

Expand Gameplane's first-party game module catalog to support all 26 top-played multiplayer games from the Steam top 100 that support user-hosted dedicated servers. The feature authors 13 new modules (`fivem`, `team-fortress-2`, `farming-simulator-25`, `euro-truck-simulator-2`, `mount-and-blade-2-bannerlord`, `tmodloader`, `beammp`, `left-4-dead-2`, `the-isle`, `ark-survival-evolved`, `arma-reforger`, `hell-let-loose`, `squad`) and standardizes the 13 existing modules (`cs2`, `palworld`, `rust`, `project-zomboid`, `dayz`, `garrys-mod`, `terraria`, `7-days-to-die`, `ark-survival-ascended`, `factorio`, `dont-starve-together`, `valheim`, `satisfactory`). Each module delivers a complete package (`module.yaml`, `template.yaml`, `README.md`, `specs.md`, `samples/gameserver.yaml`) that passes `modules/validate.py`.

The original plan scoped this as a modules-only change. During task generation the maintainer widened it, and the shipped feature also includes:

- **Two new `spec.rcon.protocol` values, `rest` and `cli`**, implemented end to end: CRD enum (`operator/api/v1alpha1/gametemplate_types.go:1006`), regenerated CRDs and module schema, agent clients (`agent/internal/rcon/rest.go`, `cli.go`) and dispatch (`agent/cmd/main.go`), operator secret handling (`operator/internal/controller/helpers.go`, `gameserver_rcon.go`), dashboard gating (`web/src/lib/capabilities.ts` `rconAvailable`), validator (`modules/validate.py` `RCON_PROTOCOLS`), and docs (`docs/module-authoring.md`, `agent/specs.md`).
- **Gameplane-owned images** for the four auxiliary-service and token-diagnostic games (`fivem`, `farming-simulator-25`, `euro-truck-simulator-2`, `beammp`): a `Dockerfile` and `entrypoint.sh` in each module directory, built, pushed and cosign-signed by `modules/build-images.sh` (research.md Decision 1).
- **13 new wire-protocol probe packages** under `test/e2e/internal/<game>/`, plus bot, RCON, persistence and mods e2e tests registered in `test/e2e/buckets.sh` and the `fastGameSet`/`heavyGameSet` scopes in `test/e2e/gamebot_helpers_e2e_test.go`.
- **A validator layout rule** (ERROR when `README.md`, `specs.md` or a non-empty `samples/` is missing, opt-in for the 26 in-scope modules) with its harness `modules/test-validate-py.sh`, and the game coverage register `docs/game-coverage.md`.

Unresolved questions and per-module findings are tracked in [OPEN-DECISIONS.md](./OPEN-DECISIONS.md). The per-module planning matrix is [engine-matrix-resolved.md](./engine-matrix-resolved.md); where it differs from a shipped `modules/<name>/template.yaml`, the template is authoritative (see Known Gaps).

## Technical Context

**Language/Version**: YAML (Kubernetes CRD and JSON Schema), Markdown (`specs.md`, `README.md`), Python 3.9+ (`modules/validate.py`), Go 1.25 (agent RCON clients, operator controller, `test/e2e/` probes and tests), TypeScript (strict, one gating change in `web/src/lib/capabilities.ts`), Bash and Dockerfile (Gameplane-owned images)

**Primary Dependencies**: `GameTemplate` CRD v1alpha1 (controller-runtime + kubebuilder codegen), module JSON Schemas generated by `make module-schema`, community OCI images (SteamCMD, LinuxGSM-style, cm2network, thijsvanloef, factoriotools and similar), Wine plus a dummy X11 display for Farming Simulator 25, cosign for image signing

**Storage**: Kubernetes PersistentVolumeClaims mounted at game-specific save/config paths that never shadow the image entrypoint

**Testing**: Static preflight (`python3 modules/validate.py`, `modules/test-validate-py.sh`), Go unit tests for `rest.go`/`cli.go` (agent coverage gate 90%), operator envtest for the `cli` secret path, vitest for `rconAvailable`, and Kind e2e: wire-protocol probes proven fail-dead/succeed-live, bot tests for all 13 new games, RCON tests (TF2, Squad), persistence tests (FiveM, ARK cluster), mods test (tModLoader). All 13 new games run in the `bot-heavy` CI bucket. All suites run in CI only (CLAUDE.md rule 8).

**Target Platform**: Kubernetes / k3s, Linux amd64 (arm64 where the upstream image publishes it)

**Project Type**: Game module catalog plus supporting changes to the operator, agent, dashboard and e2e suite

**Performance Goals**: Pod creation to running container under 30 seconds, excluding image pull and first SteamCMD download (SC-004); 0% data loss across restarts (SC-005)

**Constraints**: Immutable `@sha256:` digest pinning; explicit `runAsUser`/`fsGroup`/`HOME`; non-crashing diagnostic idle when a registration token is missing (FR-013); auxiliary services supervised in the single game container (FR-012); the `rcon.protocol` enum addition is additive and non-breaking

**Scale/Scope**: 26 modules (13 new, 13 standardized), 26 `specs.md`, 26 samples, 10 `rcon.protocol` values, 4 Gameplane-owned images, 13 new probe packages

## Known Gaps (found during the 2026-10-09 refresh)

These were found by comparing the shipped templates with this plan. They are not resolved here; each needs a fix or a maintainer ruling before the feature is closed out (T126).

1. **Placeholder image digests (FR-003, SC-002).** Ten of the 13 new modules pin `@sha256:0000…0000`: `ark-survival-evolved`, `arma-reforger`, `beammp`, `euro-truck-simulator-2`, `farming-simulator-25`, `fivem`, `hell-let-loose`, `mount-and-blade-2-bannerlord`, `squad`, `the-isle`. T119 (digest-pinning pass) is marked done, but these images were never pinned.
2. **Images with no build source.** Six templates reference `ghcr.io/valgulnecron/gameplane/<game>` images that nothing in either repository builds: `mount-and-blade-2-bannerlord`, `the-isle`, `ark-survival-evolved`, `arma-reforger`, `hell-let-loose`, `squad`. `modules/build-images.sh` builds only the four images from research.md Decision 1. Either research.md Decision 1 widens to these six (with Dockerfiles), or the templates move to community images.
3. **Stale registry owner.** All ten Gameplane-owned image refs use `ghcr.io/valgulnecron/gameplane/…`; the repositories moved to `GameplanePanel` in October 2026, and `build-images.sh`'s own usage example pushes to `ghcr.io/gameplanepanel/gameplane`.
4. **Planning matrix drift.** `engine-matrix-resolved.md` no longer matches several shipped templates, for example `palworld` stop (`save`, `shutdown 1`), `rust` stop (`server.save`, `quit`), `ark-survival-ascended` stop (`SaveWorld`, `DoExit`), `tmodloader` mount path (`/opt/terraria/config`), and the CI bucket for `tmodloader`/`beammp` (shipped in `bot-heavy`, matrix says `bot-fast`). The templates are authoritative.

## Complexity Tracking

| Aspect | Justification | Simpler Alternative Rejected Because |
|---|---|---|
| Single-pod auxiliary services | Bundling txAdmin and an embedded DB in the FiveM container (and the web admin portal in FS25) avoids multi-pod scheduling in homelab clusters | Multi-pod Helm sub-charts need PVC sharing and service discovery |
| Gameplane-owned images for 4 games | Only an entrypoint Gameplane controls can guarantee FR-012 supervision and FR-013 diagnostic idle | Community images crash-loop on a missing token or cannot co-supervise companion services |
| New `rest` protocol with per-game adapters | txAdmin and the FS25 web admin use different paths, auth and envelopes; adapters behind one client keep the CRD unchanged | A bespoke protocol per game grows the enum; one fixed envelope fits neither API |
| New `cli` protocol | Lets the agent drive stop sequences and scheduled commands over a local pipe without minting a password Secret | `none` + `consoleMode: pty` gives the dashboard a console but gives the agent no command path |
| Heavy-server CI bucket | Committed tests for >8 GB games run in `bot-heavy` with documented justification | Skipping violates Principle I; standard runners OOM or run out of disk |
