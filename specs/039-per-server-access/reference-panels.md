# Per-server permission comparison

This is a design benchmark for #1063, checked November 22, 2026. An administrator should be able to reproduce a reference panel's narrow grant wherever Gameplane supports the underlying operation. A reviewer should be able to give one person that grant on server A, a different grant on B, and no access to C. The [Gameplane permission catalog](contracts/permission-catalog.md) defines the proposed actions, protected fields and enforcement points. The [current feature inventory](../../FEATURES.md) describes the product baseline.

## Pterodactyl Panel 1.15.2

The stable 1.x release at this review lists **40 permission keys in 11 groups**. The subuser editor offers 39 choices. The Panel automatically includes `websocket.connect` when creating or updating a subuser. The server owner and root administrators pass the server policy automatically. Other users need the named permission on the particular server. Ordinary subuser grants consist of enumerated keys, so a newly introduced key needs a grant. [Stable release](https://github.com/pterodactyl/panel/releases/tag/v1.15.2) · [Catalog](https://github.com/pterodactyl/panel/blob/90b2aa87469da4fffd941b3c99f3c1ca48a01b78/app/Models/Permission.php#L92-L189) · [Subuser editor](https://github.com/pterodactyl/panel/blob/90b2aa87469da4fffd941b3c99f3c1ca48a01b78/resources/scripts/components/server/users/EditSubuserModal.tsx#L139-L151) · [Default grant](https://github.com/pterodactyl/panel/blob/90b2aa87469da4fffd941b3c99f3c1ca48a01b78/app/Http/Controllers/Api/Client/Servers/SubuserController.php#L150-L168) · [Server policy](https://github.com/pterodactyl/panel/blob/90b2aa87469da4fffd941b3c99f3c1ca48a01b78/app/Policies/ServerPolicy.php#L13-L32)

Read each suffix below with its group prefix. For example, `database.view_password` permits disclosure of the database credential. Each Gameplane entry is a target or an identified gap. Similar names alone do not establish equivalent access.

| Pterodactyl group | Published keys and meaning | Gameplane comparison and release check |
| --- | --- | --- |
| `websocket` | `connect` streams console output and real-time statistics. | A status viewer can inspect the server without receiving logs. A log reader can follow output with input disabled. A duplex console needs authority for both output and input. Check the initial history and the live connection. |
| `control` | `console`, `start`, `stop`, `restart`. Restart may start an offline server. Stop also gates the kill signal. [Power mapping](https://github.com/pterodactyl/panel/blob/90b2aa87469da4fffd941b3c99f3c1ca48a01b78/app/Models/Task.php#L100-L119) | Expose the supported start, stop, restart and wake actions independently. Grant a single named game action without granting raw commands or general power control. Check the corresponding API and game-specific controls. |
| `user` | `read`, `create`, `update`, `delete` apply to subusers on this server. Subusers assigning permissions must hold them and cannot edit themselves. [Assignment checks](https://github.com/pterodactyl/panel/blob/90b2aa87469da4fffd941b3c99f3c1ca48a01b78/app/Http/Requests/Api/Client/Servers/Subusers/SubuserRequest.php#L21-L71) | **D2 is settled.** Grant `members.view`, `members.invite`, `members.edit` and `members.remove` independently. Give a shift lead invite on server A. Verify they can assign an existing account a role within their transferable rights there, cannot list, edit or remove members, and cannot invite on server B. Check action and selector limits, including dormant permissions, on every mutation. Account creation, role publication and fleet bindings have separate gates. |
| `file` | `read` lists directories. `read-content` reads or downloads bytes. `create`, `update`, `delete` distinguish mutations in the catalog. The content-write endpoint checks `create`, and rename checks `update`. [Content write](https://github.com/pterodactyl/panel/blob/90b2aa87469da4fffd941b3c99f3c1ca48a01b78/app/Http/Requests/Api/Client/Servers/Files/WriteFileContentRequest.php) · [Rename](https://github.com/pterodactyl/panel/blob/90b2aa87469da4fffd941b3c99f3c1ca48a01b78/app/Http/Requests/Api/Client/Servers/Files/RenameFileRequest.php) `archive` covers compression and extraction. `sftp` gates a second transport that observes the assigned file rights. | Test listing without content access and editing without deleting. Enforce create-only without overwrite at the actual write boundary, a stronger distinction than the reference content-write endpoint. Check new and existing upload destinations. For a ZIP written to disk or streamed to a client, check every source path and any destination. The native agent file browser and HTTP transfers are comparable. Generic archive extraction is a gap. SFTP is designed separately and has no baseline implementation to compare. [Gameplane SFTP spec](../040-sftp-access/spec.md) |
| `backup` | `read`, `create`, `delete`, `download`, `restore`. Download can expose every file in a backup. Restore can replace all data. The delete permission also governs changing a backup's lock. For Restic, verify source access and restore authority on the actual target. For CSI, verify authority to create the destination server. Panel backup download and Pterodactyl-style backup locking have no matching operation in this baseline. File download or repository credentials would expose different data. |
| `allocation` | `read`, `create`, `update`, `delete` apply to server port allocations. The primary address is visible with server access. Update covers assigning the primary and editing notes. Creation respects the server limit, and the primary allocation cannot be removed. [Allocation controller](https://github.com/pterodactyl/panel/blob/90b2aa87469da4fffd941b3c99f3c1ca48a01b78/app/Http/Controllers/Api/Client/Servers/NetworkAllocationController.php#L36-L132) | Test a read-only networking operator and a narrowly authorized editor against supported network fields, including requests for an address or pool. Keep cluster inventory, host-level configuration and tunnel credentials independently protected. Native Services and address requests have no interchangeable subuser-managed allocation object or notes. |
| `startup` | `read`, `update`, `docker-image`. Eggs restrict visible and editable variables. An image change is limited to the egg's allowed choices. [Variables](https://github.com/pterodactyl/panel/blob/90b2aa87469da4fffd941b3c99f3c1ca48a01b78/app/Http/Controllers/Api/Client/Servers/StartupController.php#L30-L66) · [Image validation](https://github.com/pterodactyl/panel/blob/90b2aa87469da4fffd941b3c99f3c1ca48a01b78/app/Http/Requests/Api/Client/Servers/Settings/SetDockerImageRequest.php#L14-L28) | Test viewing and editing one declared, editable game setting and choosing a supported template version. Field validation, secret redaction, image overrides and external secret references retain their own gates. An egg image selector and a Gameplane template version can expose different choices. Rust's Save Interval is editable while its Query and RCON ports are read-only. Team Fortress 2 exposes editable Default Map and read-only Game ID. Gameplane can further restrict which editable keys a particular assignee may change. [Rust egg](https://github.com/pterodactyl/panel/blob/90b2aa87469da4fffd941b3c99f3c1ca48a01b78/database/Seeders/eggs/rust/egg-rust.json#L124-L159) · [Team Fortress 2 egg](https://github.com/pterodactyl/panel/blob/90b2aa87469da4fffd941b3c99f3c1ca48a01b78/database/Seeders/eggs/source-engine/egg-team-fortress2.json#L35-L50) |

Panel SQLite/PostgreSQL storage, backup repositories and game environment values do not fill this row. If game databases ship, credential rotation and disclosure need separate checks. |
| `schedule` | `read`, `create`, `update`, `delete`. Update includes task editing and triggering an existing schedule. Authoring a command, power or backup task checks the corresponding action. An already admitted schedule can be triggered with schedule-update authority. [Task authorization](https://github.com/pterodactyl/panel/blob/90b2aa87469da4fffd941b3c99f3c1ca48a01b78/app/Http/Requests/Api/Client/Servers/Schedules/StoreTaskRequest.php#L15-L44) · [Execution policy](https://github.com/pterodactyl/panel/blob/90b2aa87469da4fffd941b3c99f3c1ca48a01b78/app/Http/Controllers/Api/Client/Servers/ScheduleController.php#L140-L159) | Exercise distinct read, create, update and delete choices for native backup schedules. | `settings` | `rename` changes the displayed server name and description. `reinstall` triggers installation again. | Allow editing an exposed description independently of sensitive settings. The GameServer object's name and UID identify the workload. Wipe, clone, version changes and restore have distinct effects and authorizers. None establishes a Pterodactyl reinstall capability. |

## CubeCoders AMP

AMP 2 provides a second benchmark for **how permissions compose**, particularly in a panel serving many games. CubeCoders' knowledge base contains a community-contributed description of controller and instance scope. Developer statements and release notes below document conflict resolution, delegated assignment and field-level settings.

| AMP 2 behavior | Gameplane comparison and release check |
| --- | --- |
| The ADS controller and each game instance have distinct functions. Roles created at the controller can be configured across instances. Accounts and roles created within one instance are local to it. One user can hold several roles. [AMP 2 permissions guide](https://discourse.cubecoders.com/t/managing-user-permissions-in-amp/2301) | Gameplane has three access layers. A panel role governs installation settings. A cluster/namespace role can permit provisioning at a selected placement. Its membership grants the selected base role on every server in scope, with any selected GameTemplate roles added on compatible servers. A direct membership grants live roles or custom actions on one server UID. Invitation choices start blank and require selection. Give an account with **Assigned servers only** different responsibilities on two siblings. Verify discovery, direct URLs, counts and administrative boundaries. Local per-instance account creation is a different identity model. |
| A role can allow, deny or leave a permission unset. An explicit deny wins over another role's allow. Template roles can apply across instances, including ADS itself. [CubeCoders explanation](https://discourse.cubecoders.com/t/network-edition-template-user-permissions-propagate-to-controller/521/4) | Removing a direct role permission removes only that source’s contribution. **D6 is settled.** Only the built-in primary panel admin can add, edit or remove a scoped **Block**. A matching Block overrides ordinary direct and inherited allows. Test a blocked action on server A, its permitted use on sibling B, and an owner, target admin or delegate attempting to change the Block. Preserve the primary panel admin’s recovery authority. |
| AMP 2 supports permissions on settings at section and individual field level. Settings nodes are shared by configuration and the API, and a node rename can require migrating stored grants. [CubeCoders settings change](https://discourse.cubecoders.com/t/potential-breaking-change-notification/7900) | Grant edit for one declared key on one game. Authorize its canonical ID on every API/form entry point. Show the allowed value and preserve validation. Reject a mixed request containing a protected neighbor. New game keys and named actions require explicit selection. Check a module change that removes or renames a key. |
| AMP templates expose different settings per game. Terraria defines separate Max Players and Password fields. Valheim defines independent lists for admins, permitted players and banned players. Field declarations establish the configuration surface. The separate AMP permission documentation establishes the per-setting model. [Terraria schema](https://github.com/CubeCoders/AMPTemplates/blob/9cb9c83b4127e441138912badfdd8ae96cb97018/terrariaconfig.json#L113-L140) · [Valheim schema](https://github.com/CubeCoders/AMPTemplates/blob/9cb9c83b4127e441138912badfdd8ae96cb97018/valheimconfig.json#L171-L195) | Test the Gameplane analogues: edit a reviewed player-limit key without password access, and delegate allowlisting independently of banning on a module that declares both. A control from a different product's Valheim template does not establish Gameplane Valheim support. |
| AMP restricts adding people to roles whose permissions the grantor lacks. Locally created users have a restricted user listing. [CubeCoders permissions update](https://discourse.cubecoders.com/t/amp-decadeus-2-4-3-release-notes/3319) | Reject delegation beyond the grantor’s transferable rights on the target, including dormant actions and wider folder or field selectors. Require the appropriate membership permission. A later primary panel admin edit to the role reaches all assignees. Test that a manager with invite alone can select an exact account without listing members or browsing the global directory. |
| Controller roles, instance roles and templates can serve different groups of instances. [AMP 2 permissions guide](https://discourse.cubecoders.com/t/managing-user-permissions-in-amp/2301) · [Template scope](https://discourse.cubecoders.com/t/network-edition-template-user-permissions-propagate-to-controller/521/4) | **D5 is settled.** Bind a namespace role with Viewer and the CS2 template’s Match referee addition. Preview two current servers and future coverage. Verify that existing CS2 A receives both sources, existing Valheim B receives Viewer, and new CS2 C automatically receives both. A same-named namespace in a different cluster is outside the grant. Repeat with the whole-cluster scope across two namespaces. Existing panel-role mappings via OIDC/Helm retain their scope. |

**AMP 3 public beta.** CubeCoders describes a central editor for individual servers, creator-scoped rules and exceptions. Gameplane supports scoped inheritance and direct server assignments alongside its owner checks. Automatic grants across servers based on creator identity and free-form policy expressions are outside #1063. Its admin-only Block can restrict existing access on one server or within an exact cluster/namespace. [AMP 3 announcement](https://discourse.cubecoders.com/t/announcing-amp-3/41039) · [CubeCoders walkthrough](https://www.reddit.com/r/Amp/comments/1w0sicu/we_made_permissions_not_suck_in_amp_3/)

The November 19, 2026 release notes for 3.0.2 describe folder permissions across the file manager and SFTP, and hiding inaccessible pages and actions. For Gameplane, grant an exact path or subtree under the server data root. Check the dashboard and API for access to that path, denial on a sibling and refusal of a ZIP spanning both. These tests cover Gameplane's native transports. Verify the same cases on the optional transport before claiming SFTP parity. [Gameplane SFTP spec](../040-sftp-access/spec.md) [AMP 3.0.2 beta release notes](https://discourse.cubecoders.com/t/amp-3-beta-neptune-v3-0-2-release-notes/43715)

## Evidence required for release

1. For every comparable operation, record an allowed request and a denied neighboring operation using the same account. For direct-only access, repeat on an unassigned sibling. For inherited access, repeat on a sibling with the matching template, one with a different template and a same-named server outside the binding. Record the dashboard result and the API, stream or transfer result, as applicable.
2. Use actual module declarations from at least two game families. For example, allow a named Counter-Strike 2 match action on one server and one typed setting on a Terraria or Palworld server. Check raw console input, an unselected action or setting, and a module without the capability. A control labelled “game action” alone does not establish per-action authorization.
3. Exercise access changes through an existing connection. Change a live base role, remove an assignment, and retain an independent fleet grant. Verify which action ceased, which survived and which source supplied it. Verify that a new template role appears as an assignable option and that changing a published action’s meaning requires review. Approved live role edits reach direct and inherited assignees. Installing a template cannot assign people to a role.
4. Record the tests for independent delegation (D2), panel, cluster/namespace and individual server access (D5), and admin-only Blocks (D6). Preview current server and template counts and future coverage, add a namespace grant in **Cluster → Roles & permissions**, verify its inherited sources on the person’s access page and remove it there. Check all three base roles, missing-base validation and a new matching server. Both views should agree on revocation while the person retains an independent direct server assignment. Verify that server assignment alone cannot change panel settings, provision a new server or grant access to siblings. For each missing feature, identify the missing operation or scope.
