# Per-server permission comparison

This is a design benchmark for #1063, with reference products checked November 22, 2026 and Gameplane updated to `aa3b64f9` on November 26. An administrator should be able to reproduce a reference panel's narrow grant wherever Gameplane supports the underlying operation. A reviewer should be able to give one person that grant on server A, a different grant on B, and no access to C. The [Gameplane permission catalog](contracts/permission-catalog.md) defines the proposed actions, protected fields and enforcement points. The [current feature inventory](../../FEATURES.md) describes the product baseline.

## Pterodactyl Panel 1.15.2

The stable 1.x release at this review lists **40 permission keys in 11 groups**. The subuser editor offers 39 choices. The Panel automatically includes `websocket.connect` when creating or updating a subuser. The server owner and root administrators pass the server policy automatically. Other users need the named permission on the particular server. Ordinary subuser grants consist of enumerated keys, so a newly introduced key needs a grant. [Stable release](https://github.com/pterodactyl/panel/releases/tag/v1.15.2) · [Catalog](https://github.com/pterodactyl/panel/blob/90b2aa87469da4fffd941b3c99f3c1ca48a01b78/app/Models/Permission.php#L92-L189) · [Subuser editor](https://github.com/pterodactyl/panel/blob/90b2aa87469da4fffd941b3c99f3c1ca48a01b78/resources/scripts/components/server/users/EditSubuserModal.tsx#L139-L151) · [Default grant](https://github.com/pterodactyl/panel/blob/90b2aa87469da4fffd941b3c99f3c1ca48a01b78/app/Http/Controllers/Api/Client/Servers/SubuserController.php#L150-L168) · [Server policy](https://github.com/pterodactyl/panel/blob/90b2aa87469da4fffd941b3c99f3c1ca48a01b78/app/Policies/ServerPolicy.php#L13-L32)

Read each suffix below with its group prefix. For example, `database.view_password` permits disclosure of the database credential. Each Gameplane entry is a target or an identified gap. Similar names alone do not establish equivalent access.

## CubeCoders AMP

AMP 2 provides a second benchmark for **how permissions compose**, particularly in a panel serving many games. CubeCoders' knowledge base contains a community-contributed description of controller and instance scope. Developer statements and release notes below document conflict resolution, delegated assignment and field-level settings.

| AMP 2 behavior | Gameplane comparison and release check |
| --- | --- |
| The ADS controller and each game instance have distinct functions. Roles created at the controller can be configured across instances. Accounts and roles created within one instance are local to it. One user can hold several roles. [AMP 2 permissions guide](https://discourse.cubecoders.com/t/managing-user-permissions-in-amp/2301) | Gameplane has three access layers. A panel role governs installation settings. A cluster or namespace role can permit provisioning at a selected placement with no inherited server roles. Scope membership alone supplies no `server.view`. Where an admin adds named server roles, each grants its permissions on matching current and future servers. Choosing only a published GameTemplate role grants its visibility and controls on matching servers. Other games stay hidden unless an independent grant makes them visible. A selected shipped base carries its approved declared additions and active recommendations on matching templates. A direct membership grants live roles or custom actions on one server UID. Invitation choices start blank and require selection. Give an account with **Assigned servers only** different responsibilities on two siblings. Verify discovery, direct URLs, counts and administrative boundaries. Local per-instance account creation is a different identity model. |
| A role can allow, deny or leave a permission unset. An explicit deny wins over another role's allow. Template roles can apply across instances, including ADS itself. [CubeCoders explanation](https://discourse.cubecoders.com/t/network-edition-template-user-permissions-propagate-to-controller/521/4) | Removing a direct role permission removes only that source’s contribution. **D6 is settled.** Only the built-in primary panel admin can add, edit or remove a scoped **Block**. A matching Block overrides ordinary direct and inherited allows. Test a blocked action on server A, its permitted use on sibling B, and an owner, target admin or delegate attempting to change the Block. Preserve the primary panel admin’s recovery authority. |
| AMP 2 supports permissions on settings at section and individual field level. Settings nodes are shared by configuration and the API, and a node rename can require migrating stored grants. [CubeCoders settings change](https://discourse.cubecoders.com/t/potential-breaking-change-notification/7900) | Grant edit for one declared key on one game. Authorize its canonical ID on every API/form entry point. Show the allowed value and preserve validation. Reject a mixed request containing a protected neighbor. New game keys and named actions require explicit selection. Check a module change that removes or renames a key. |
| AMP templates expose different settings per game. Terraria defines separate Max Players and Password fields. Valheim defines independent lists for admins, permitted players and banned players. Field declarations establish the configuration surface. The separate AMP permission documentation establishes the per-setting model. [Terraria schema](https://github.com/CubeCoders/AMPTemplates/blob/9cb9c83b4127e441138912badfdd8ae96cb97018/terrariaconfig.json#L113-L140) · [Valheim schema](https://github.com/CubeCoders/AMPTemplates/blob/9cb9c83b4127e441138912badfdd8ae96cb97018/valheimconfig.json#L171-L195) | Test the Gameplane analogues: edit a reviewed player-limit key without password access, and delegate allowlisting independently of banning on a module that declares both. A control from a different product's Valheim template does not establish Gameplane Valheim support. |
| AMP restricts adding people to roles whose permissions the grantor lacks. Locally created users have a restricted user listing. [CubeCoders permissions update](https://discourse.cubecoders.com/t/amp-decadeus-2-4-3-release-notes/3319) | Reject delegation beyond the grantor’s transferable rights on the target, including dormant actions and wider folder or field selectors. Check `members.*` on one server or the selected `bindings:*` operation within a cluster or namespace. Rights to edit a reusable definition are separate. A later primary panel admin edit to the role reaches all assignees. Test that a manager with member view and invite can select an exact account without browsing the global directory. |
| Controller roles, instance roles and templates can serve different groups of instances. [AMP 2 permissions guide](https://discourse.cubecoders.com/t/managing-user-permissions-in-amp/2301) · [Template scope](https://discourse.cubecoders.com/t/network-edition-template-user-permissions-propagate-to-controller/521/4) | **D5 is settled.** Bind a namespace role with only the CS2 template’s Match referee role. Preview one CS2 match among the two current servers and its future matches. Verify that the role’s `server.view` and referee actions apply on CS2 A and future CS2 C. Without independent grants, Valheim B and a future Terraria server are hidden from lists, counts and direct links. A same-named namespace in a different cluster is outside the grant. Repeat with the whole-cluster scope across two namespaces. Existing panel-role mappings via OIDC/Helm retain their scope. |

**AMP 3 public beta.** CubeCoders describes a central editor for individual servers, creator-scoped rules and exceptions. Gameplane supports scoped inheritance and direct server assignments alongside its owner checks. Automatic grants across servers based on creator identity and free-form policy expressions are outside #1063. Its admin-only Block can restrict existing access on one server or within an exact cluster/namespace. [AMP 3 announcement](https://discourse.cubecoders.com/t/announcing-amp-3/41039) · [CubeCoders walkthrough](https://www.reddit.com/r/Amp/comments/1w0sicu/we_made_permissions_not_suck_in_amp_3/)

The November 19, 2026 release notes for 3.0.2 describe folder permissions across the file manager and SFTP, and hiding inaccessible pages and actions. For Gameplane, grant an exact path or subtree under the server data root. Check the dashboard and API for access to that path, denial on a sibling and refusal of a ZIP spanning both. Repeat the supported file operations over SFTP with `sftp.connect` and each required file grant on that server, including a refused rename across the folder boundary. Revoke SFTP alone and verify a separate Files-tab grant still works. ## Evidence required for release

1. For every comparable operation, record an allowed request and a denied neighboring operation using the same account. For direct-only access, repeat on an unassigned sibling. For inherited access, repeat on a sibling with the matching template, one with a different template and a same-named server outside the binding. Record the dashboard result and the API, stream or transfer result, as applicable.
2. Use actual module declarations from at least two game families. For example, allow a named Counter-Strike 2 match action on one server and one typed setting on a Terraria or Palworld server. Check raw console input and an unselected action or setting. Test typed Kick and Ban separately on a supported module, a kick-only fixture and a module that supplies only a roster. An unsupported operation must never reach the game through its control, direct API or a named action. On a supported server, block `players.ban` for someone with effective `console.send`. Verify that the panel and named Ban actions are denied, raw game input still works and the preview explains the remaining console authority. A control labelled “game action” alone does not establish per-action authorization.
3. Exercise access changes through an existing connection. Change a live base role, remove an assignment, and retain an independent fleet grant. Verify which action ceased, which survived and which source supplied it. Verify that an approved optional template role appears as an assignable option and that changing a published action’s meaning suspends its mapping until fresh review. Approved live role edits reach direct and inherited assignees. Installing a template cannot assign people to a role.
4. Record the tests for independent delegation (D2), panel, cluster/namespace and individual server access (D5), and admin-only Blocks (D6). Preview current server and template counts and future coverage, add a namespace grant in **Cluster → Roles & permissions**, verify its inherited sources on the person’s access page and remove it there. Start with a namespace provisioner with `servers:create` and the required placement and template visibility. Leave the inherited server-role list empty. Verify the user can provision while unrelated existing servers stay hidden on direct requests. Attribute access on the server they create to ownership. Then add only CS2 Match referee. Verify existing and future CS2 servers receive its permissions and other games stay hidden. Clear the last inherited role and verify that its server access disappears while scoped provisioning and a separate direct assignment on one UID survive. Also accept a panel-created server role alone or several applicable roles. Exercise zero current matches with a future matching server. Give a user `servers:inventory` independently, verify its effect on nonmatching inventory rows, then remove it and verify those rows disappear. Verify the four shipped roles remain editable and selectable. Retire a custom role used by the namespace definition. Verify existing members still inherit it on current and future matching servers and the definition cannot be granted to another person until its retired reference is removed or replaced. Both views should agree on revocation while the person retains an independent direct server assignment. Verify that server assignment alone cannot change panel settings, provision a new server or grant access to siblings. For each missing feature, identify the missing operation or scope. A feature comparison can claim a tested workflow even when broader panel parity remains open. [Decision register](OPEN-DECISIONS.md) · [Implementation plan](plan.md)
5. Compare a narrow duty in each layer against its nearest broader grant. Exercise a credential reset without promotion, scoped assignment without role editing, selected-template provisioning without template catalog visibility, and moderation without persistent player IDs. Compare previewed and actual reads, writes and redacted fields with an independent broad grant present and again after an admin Block. Use the [panel and workload catalog](contracts/fleet-permissions.md) and [server catalog](contracts/permission-catalog.md) as the source for Gameplane keys.
6. Verify the [four shipped base roles](contracts/permission-catalog.md#default-base-server-roles) through both a direct assignment and an inherited assignment. A Viewer sees status and filtered events. A Power User can restart the server, read logs and send console input. An Operator can edit an approved file and the description, while critical settings and unreviewed paths remain inaccessible through those controls. Show the independent game authority of raw console commands in the preview. Verify a server Administrator can delete an authorized backup and manage direct members within the delegation ceiling. Server deletion, wipe, ownership transfer and panel or cluster operations still require their own authority.
7. Exercise the [GameTemplate declarations](contracts/permission-catalog.md#gametemplate-roles) with CS2 pause and resume. Approve the template’s permission set after preview. Verify the declared Administrator additions take effect in that save and the Power User recommendation stays inactive. Activate that recommendation separately and explicitly assign Match referee to a Viewer. Check direct and inherited Administrators, future matching servers, another game, an untargeted base and a custom copy of Administrator. Within one panel, reuse the approval on another cluster running the same verified module with the same reviewed permission definitions and role contributions, including through a local install alias. An unrelated source or fork using the same permission ID, a changed permission or base addition, and an installation under a different panel each need their own review. An older server still running the approved definition keeps it while a changed operation awaits review. Withdraw a declared addition and confirm that independent Match referee access survives. Repeat with a Block on the canonical action, an offline cluster and a stale approval. A future matching installation can use the panel’s existing approval. Installing a package cannot approve new permissions or restore a withdrawn grant.
