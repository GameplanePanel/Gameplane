# Implementation tasks for spec 039

The [spec](spec.md) records the three-layer role design. The [panel and workload catalog](contracts/fleet-permissions.md) and [server catalog](contracts/permission-catalog.md) define the assignable operations. The [plan](plan.md) orders implementation, the breaking 0.x beta access reset and administrator review. Open tasks describe proposed behavior.

## Permissions and storage

- [ ] T001 Register the granular actions, selectors and read projections. Map every mutation to the applicable target view, including parent visibility for creation. Enforce effective view and mutation at the same scope and selectors across all interfaces. Seed the four cumulative roles with enumerated actions and reviewed path, field and game selectors, validate template-qualified permissions, declared base additions, recommendations and optional named roles. Verify their exact effective actions across game families. [Permission catalog](contracts/permission-catalog.md)
- [x] T002 Approve four permanent, editable base roles. Viewer is for basic visibility, Power User for lifecycle, logs and console, Operator for reviewed non-critical files and the description, and Administrator for all 91 ordinary server actions subject to target and ownership rules. Invitations start without a selection. [Exact presets and verification](plan.md#1--define-actions-and-ship-the-four-base-roles)
- [ ] T003 Preserve owners, OIDC/Helm and manual primary roles, manual overrides and their logical primary binding. Reset historical supplemental bindings when activating the new model. Allow a cluster or namespace role to grant infrastructure duties with zero inherited server roles, or to include available shipped, custom or published GameTemplate roles. Evaluate the selected roles on current and future servers. A scoped binding grants no automatic server visibility. Accept a template-only selection on a mixed scope. Keep local workload assignments distinct from the primary `local/*` binding during OIDC sync and manual edits. Implement automatic primary panel-admin coverage, section-level panel permissions and scoped provisioning. [Panel and cluster authorization](plan.md#2--resolve-panel-access-and-cluster-or-namespace-grants)
- [ ] T004 Store direct memberships, zero or more server-role IDs on each scope definition with their applicable template identities, reviewed live roles, approved declared additions and independent recommendation activations keyed to template, base and source, and admin Blocks in panel SQL. Match scope grants and Blocks to the cluster registration generation and exact namespace UID where applicable. Preview an explicit rebind on replacement. Hold the affected access when a stale Block could reveal it. For every current and future server in scope, resolve the applicable roles and their explicit actions and views. Include approved base additions and active recommendations only for each shipped role actually held. Combine with direct grants and ownership. Custom copies of a base keep only their explicit grants. [Storage and effective permissions](plan.md#3--store-live-roles-and-resolve-effective-rights)
- [ ] T011 Implement granular panel account lookup, lifecycle, credential, primary-role and token duties, role authoring, section settings, cluster registration, node join and credential operations. Verify field projection, privilege ceilings, redaction and the last-primary-admin guard across concurrent manual changes. Verify the authoritative OIDC demotion exception and operator recovery when no primary admin remains. Split other-user SFTP credential inspection and revocation, per-cluster endpoint and service-token duties, and root-policy read, enable and disable. Verify the 25 existing fleet keys, including `servers:security`, against the current route and field matrix. [Panel and cluster authorization](plan.md#2--resolve-panel-access-and-cluster-or-namespace-grants)
- [ ] T012 Implement scope-eligible binding read/assign/revoke and shared scope-role authoring with scope and delegation checks on every mutation. Implement separate inventory projections, filtered audit, template use/authoring, module/source management, destination use/management and server vs node capture duties. Verify filtered lists/counts, approved-template provisioning and denial on an adjacent action or target. [Fleet permission catalog](contracts/fleet-permissions.md)
