# Implementation tasks for spec 039

The [spec](spec.md) records the three-layer role design. The [panel and workload catalog](contracts/fleet-permissions.md) and [server catalog](contracts/permission-catalog.md) define the assignable operations. The [plan](plan.md) orders their implementation and the later collaborator conversion. Open tasks describe proposed behavior.

## Permissions and storage

- [ ] T001 Register the granular actions, selectors and read projections. Seed the approved base roles, validate template-qualified role definitions and verify their exact effective actions across game families. [Permission catalog](contracts/permission-catalog.md)
- [x] T002 Approve the three shipped base roles: Viewer, Power User and Administrator. Administrator includes every Power User permission plus the player roster, kick, backup listing and backup creation. Invitations start without a selection. [Base roles and template roles](plan.md#1--define-actions-and-ship-the-three-base-roles)
- [ ] T003 Preserve primary OIDC/Helm assignments and existing supplemental grants. Require exactly one base server role on new cluster/namespace roles, and an explicit previewed choice before converting historical grants. Keep the local workload’s whole-cluster grant distinct from the primary `local/*` binding during OIDC sync and manual editing. Implement automatic primary panel-admin coverage, section-level panel permissions and scoped provisioning. [Panel and cluster authorization](plan.md#2--resolve-panel-access-and-cluster-or-namespace-grants)
- [ ] T004 Store direct memberships, scope-role base and GameTemplate references, reviewed live roles and admin Blocks in panel SQL. For every current and future server in scope, resolve its inherited base and matching template roles alongside direct grants and ownership. [Storage and effective permissions](plan.md#3--store-live-roles-and-resolve-effective-rights)
- [ ] T011 Implement granular panel account lookup, lifecycle, credential, primary-role and token duties, role authoring, section settings, cluster registration, node join and credential operations. Verify field projection, privilege ceilings, last-admin protection and redaction. Freeze the broad fleet permission behavior against the baseline route and field matrix. [Panel and cluster authorization](plan.md#2--resolve-panel-access-and-cluster-or-namespace-grants)
- [ ] T012 Implement scope-eligible binding read/assign/revoke and shared scope-role authoring with scope and delegation checks on every mutation. Implement separate inventory projections, filtered audit, template use/authoring, module/source management, destination use/management and server vs node capture duties. Verify filtered lists/counts, approved-template provisioning and denial on an adjacent action or target. [Fleet permission catalog](contracts/fleet-permissions.md)
