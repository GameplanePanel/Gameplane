# Feature Specification: Split big packages and files

**Feature Branch**: `claude/project-thread-oxpa6z`

**Created**: 2026-10-20

**Status**: Draft

**Input**: User description: "Write a speckit spec (spec, plan, tasks) for the Gameplane v1 cleanup 'split big packages and files'. Behaviour-preserving moves and splits only, following the target layout from spec 027, keeping spec 023's path mapping valid."

## Context

v1 is the 20 audit issues #712–#731 plus codebase cleanup, with no new features (valgul,
2026-10-20). This is one of three cleanup specs. Spec 027 (contributor docs and layout map)
defines the target layout; this spec applies it to the code. Spec 029 (faster e2e buckets)
waits for spec 023.

Target layout, settled in spec 027 (`specs/027-contributor-docs-layout-map/OPEN-DECISIONS.md`,
valgul 2026-10-20). This spec applies it and does not reopen it:

- **027 OD-3, Go modules.** Long-running services use a thin `cmd/main.go` plus
  `internal/<concern>/` packages, as `api`, `operator`, `agent` and `capture-sidecar`
  already do. Libraries (`netguard`, `gameaction`, `gameproto`, `svcutil`,
  `telemetryschema`, `i18n`) stay one flat root package. CLIs use `cmd/<binary>/`.
- **027 OD-4, web.** One `web/src/pages/<Screen>.tsx` per screen. A screen over 500 lines
  is split into section files under `pages/<Screen>/` (for example `Footer.tsx`,
  `UpperSection.tsx`) that `pages/<Screen>.tsx` composes. `routes/` only exposes pages.
  `components/` holds parts used by two or more screens. Tests stay next to the file they
  test.
- **027 OD-5, enforcement.** This spec adds a folder-shape layout check to `make lint` once
  every module matches the layout.
- **027 OD-2.** Each module keeps its `specs.md` (constitution IV, `hack/check-specs.sh`).
  Every move updates the paths that module's `specs.md` names.

## User Scenarios & Testing *(mandatory)*

The users of this change are contributors (valgul, outside contributors, and agents) who
read, review and change the code. Players and operators of a Gameplane install must see
no difference.

### User Story 1 - Small Go services match the service layout (Priority: P1)

A contributor opening `tunnel/`, `sentinel/`, `telemetry-receiver/`,
`audit-syslog-bridge/` or `mcp-server/` finds the same shape as `api/`: a thin
`cmd/main.go` and `internal/<concern>/` packages, each concern in its own file set,
instead of one 1,000-line `main.go` or 30 flat files.

**Why this priority**: the layout is settled, the modules are small, and they prove the
move script, the review method and the "nothing changed" checks on low-risk code before
the two big packages.

**Independent Test**: one PR per service; CI runs that module's unit tests, its e2e
suites (`ci: full-run`), its image build and the coverage gate, all green, with the same
test names passing as on master.

**Acceptance Scenarios**:

1. **Given** `tunnel/main.go` (1,052 lines), **When** its PR merges, **Then** `tunnel/cmd/main.go` holds only flag/env parsing and wiring, the logic lives under `tunnel/internal/<concern>/`, the three tunnel images build from the new entry point, and every test that passed before passes after.
2. **Given** a service whose image is built by a Dockerfile, **When** the entry point moves, **Then** the Dockerfile, Makefile and chart references point to the new path in the same PR and the built image starts with the same command line and environment.
3. **Given** a library module (`netguard`, `gameaction`, `gameproto`, `svcutil`, `telemetryschema`, `i18n`), **When** this spec is done, **Then** it is unchanged (027 OD-3 keeps libraries flat).

### User Story 2 - API handlers are split into sub-packages (Priority: P2)

A contributor fixing a capture or users bug opens a sub-package that holds only that
area's handlers and tests, not a 146-file package.

**Why this priority**: the API package is the most edited package in the audit fixes and
the second-largest flat package. Splitting it also lets spec 023's package-level test
selection (023 research R4) run fewer tests per change.

**Independent Test**: one PR per extracted group; CI's api unit and envtest suites and
every e2e suite pass with the same test names, and the api coverage minimum (80) holds.

**Acceptance Scenarios**:

1. **Given** a resource group (OD-2), **When** its PR merges, **Then** the group's production files and their tests live in the new sub-package, routes are mounted from `api/cmd/main.go` exactly as before (same paths, methods, middleware order), and the OpenAPI document is byte-identical.
2. **Given** `capture.go` (1,569 lines), **When** the capture group moves, **Then** it is also split into files of 500 lines or fewer (OD-3).

### User Story 3 - Operator controllers are split into sub-packages (Priority: P2)

A contributor working on backups opens a package that holds the backup, schedule and
restore reconcilers and their tests, not 150 files that also hold the GameServer
reconciler.

**Why this priority**: same as US2. Ordered against US2 by OD-1.

**Independent Test**: one PR per extracted group; CI's operator unit and envtest suites

**Acceptance Scenarios**:

1. **Given** a reconciler group, **When** its PR merges, **Then** `operator/cmd/main.go` registers the same reconcilers with the same options, `make generate && make manifests` produces no diff, and the RBAC markers produce the same ClusterRole.
2. **Given** `gameserver_controller.go` (2,740 lines) and `gameserver_status.go` (1,446), **When** the GameServer group is split, **Then** each production file is 500 lines or fewer (OD-3).

### User Story 4 - Web screens follow the pages layout (Priority: P2)

A contributor looking for the admin settings screen finds `web/src/pages/AdminSettings.tsx`
composing section files under `pages/AdminSettings/`, each under 500 lines, while
`routes/` holds one route-definition file per page (OD-7) and the server-detail tabs sit in `pages/ServerDetail/tabs/` (OD-8).

**Why this priority**: settled by 027 OD-4; the four biggest screens are the largest web
files. Ordered against US2/US3 by OD-1.

**Independent Test**: one PR per screen (or per small group of screens under 500 lines
that only move); CI's Vitest suite, ESLint, `tsc`, Playwright mock suite and visual-diff
pass, with the same test names, and the web thresholds (92/76/82/92) hold.

**Acceptance Scenarios**:

1. **Given** `routes/AdminSettings.tsx` (2,478 lines), **When** its PR merges, **Then** `pages/AdminSettings.tsx` and its section files render the same DOM (visual-diff and screenshot suites unchanged), and its tests sit next to the file they test.
2. **Given** a part used by two or more screens, **When** it is extracted, **Then** it goes to `components/`; a part used by one screen stays under that screen's `pages/<Screen>/`.
3. **Given** `web/src/types.ts`, **When** this spec is done, **Then** it stays hand-written and is split by domain into files of 500 lines or fewer behind a `types.ts` that re-exports them, so every `@/types` import keeps working; the generated `web/src/api/types.ts` is untouched (OD-5).

### User Story 5 - The layout and size rules stay true (Priority: P3)

After the last move, `make lint` fails a PR that adds a flat file at a service module's
root, a screen file outside `pages/`, or a production file over 500 lines (OD-4).

**Why this priority**: 027 OD-5 hands the check to this spec; it can only turn on once
every module conforms, so it comes last.

**Independent Test**: the check passes on the final master, and fails on a scratch tree
with one violation (run by the check's own unit test in CI, not by a throwaway PR).

**Acceptance Scenarios**:

1. **Given** every module conforms, **When** the layout check is added to `make lint`, **Then** master is green.
2. **Given** a PR that puts `foo.go` (not `main.go`-only wiring) at a service module root, **When** CI runs, **Then** lint fails naming the file and the rule from `docs/layout.md`.

### Edge Cases

- **Unexported identifiers across new package lines.** (OD-2: by resource.) Moving code into sub-packages turns calls between groups into cross-package calls. Only the identifiers that must cross are exported, with the same behaviour; renames are mechanical (`gopls rename` or `gofmt -r`), never hand-edited logic. Shared helpers used by several groups go to one internal helper package per module, not duplicated.
- **Import cycles.** If two groups call each other, the shared part moves down to the helper package. A group that cannot be cut without a cycle stays in the parent package and is recorded in `research.md` with the cycle.
- **envtest suites.** Today each big package starts one envtest control plane in one `TestMain`. A sub-package with envtest tests needs its own `TestMain`, which is new test setup (OD-6) and adds one control-plane start per sub-package to CI time; the plan measures it.
- **Path-based configs.** `.golangci.yml` path exclusions (for example `internal/handlers/capture\.go$` for gosec, `internal/controller/` for revive `exported:`), `.testcoverage.yml` `exclude.paths`, `vitest.config.ts` `coverage.exclude`, `.coderabbit.yaml` path rules, Dockerfiles and Makefile targets name paths. Each move updates them in the same PR to the new path, with the same scope; no exclusion is widened.
- **Spec 023 mapping.** Components are whole module directories (`ci_scope.py` reads `go.work`), so moves inside a module keep them valid. File-level entries (`suite-components.json` `paths`, `file_consumers`, any test fixture path) are checked in every PR. Package-level selection (023 R4) reads import lines and follows moves on its own.
- **Spec 023 changed-lines gate.** A partial run checks coverage of "added" lines; a move shows every moved line as added, so a file already below the module minimum would fail the gate though nothing changed. Every move PR therefore carries the `ci: full-run` label (023 OD-7), which keeps the module-wide gate.
- **Open PRs and the audit fixes.** A move PR conflicts with any open PR touching the same files. Each move PR checks open PRs on its paths first and, when one exists, waits for it or agrees the order with valgul.
- **Generated files.** `zz_generated.deepcopy.go`, `operator/config/{crd,rbac}` and `web/src/api/types.ts` are never split by hand. CRD types (`operator/api/v1alpha1/*_types.go`, e.g. `gametemplate_types.go` 1,260 lines) are API surface and exempt from the ceiling (OD-3).
- **`.pen` files.** `telemetry-receiver/telemetry-dashboard.pen` and `design.pen` stay where they are and are never read or edited (CLAUDE.md rule 2).
- **No UI change.** Splitting a screen must not change DOM, styles or text. If a split needs a markup change to compose, it stops and asks; design changes go through `design.pen` first, which is out of scope here.

## Requirements *(mandatory)*

### Functional Requirements

**Scope and behaviour**

- **FR-001**: Every change in this spec MUST be behaviour-preserving: no change to any REST route, WebSocket message, CRD schema, RBAC rule, Helm value, container entry point behaviour, environment variable, log line, metric name or rendered UI.
- **FR-002**: Every change MUST be a move or a split of existing code: file moves (`git mv`), moving declarations between files, moving declarations between packages with the mechanical edits that requires (package clause, imports, exporting identifiers that cross the new boundary), and updating path references. No logic is rewritten, no dead code is removed, no dependency is added (except where OD-5 says otherwise).
- **FR-003**: The resulting layout MUST follow spec 027 OD-3 (Go) and OD-4 (web) and `docs/layout.md` once it lands.

**Tests**

- **FR-004**: Tests move with their code. A test file moved with `git mv` and no content change is a move and needs no sign-off.
- **FR-005**: The only edits allowed inside a test file are the mechanical ones the move forces, listed exactly: the `package` clause, import lines, qualified names of identifiers that moved package (`foo` → `pkg.Foo`), relative import or `vi.mock` path strings, and a new `TestMain`/suite file for a new sub-package that copies the existing envtest setup unchanged except one extra `".."` per extra folder level in its CRD paths (OD-9). valgul signed off on exactly these edit kinds for the whole spec (OD-6 2026-10-20, OD-9 2026-10-21); each PR lists every touched test file and a script proves no other kind of line changed. No assertion, test name, table entry, timeout, skip or fixture changes.
- **FR-006**: Every PR MUST show a test-name parity report: the sorted list of test names (Go `go test -list` style names collected from CI output, Vitest and Playwright test titles) before and after is identical. A missing test fails the PR.
- **FR-007**: Test files are exempt from the ceiling and are not split (OD-4).

**Proof that nothing changed**

- **FR-008**: Each PR MUST pass the full CI suite on both architectures with the `ci: full-run` label: unit, envtest, every e2e bucket, web unit, Playwright mock, visual-diff, image builds, lint, `check-specs`.
- **FR-009**: The coverage minimums in CLAUDE.md MUST hold for every touched module on the full run (netguard 91, gameaction 91, gameproto 90, telemetryschema 90, i18n 90, gp-module 80, operator 72, api 80, agent 90, svcutil 90, the 70-gated services, web 92/76/82/92). No threshold or exclusion is lowered or widened.
- **FR-010**: Generated outputs MUST be unchanged: `make generate && make manifests` produces no diff, `api/docs/openapi.yaml` is byte-identical, and the route table printed by the API at startup (or its test equivalent) is identical.
- **FR-011**: Every moved-and-unchanged file MUST be detected as a rename by git (`git diff -M --stat` shows `R100` or near it) so review can skip it; every PR description lists files that changed content beyond the FR-002/FR-005 mechanical edits, and that list is expected to be empty except for split files.
- **FR-012**: Locally only compile checks run (`go build ./...`, `npx tsc --noEmit`); tests and lint run only in CI (CLAUDE.md rule 8).

**Slicing and process**

- **FR-013**: Work MUST be sliced one package (or one service module, or one screen) per PR, in the order OD-1 sets: web, then api, then operator, then the small services (tunnel and sentinel after their audit fixes #721–#723, #729 merge). A PR touches one module, except for the path-reference updates the move forces elsewhere (Dockerfile, Makefile, docs, specs.md, 023 mapping).
- **FR-014**: Mechanical moves MUST be done by a committed, reviewed script per PR (CLAUDE.md rules 13, 17, 18): one scout writes the move list (file → destination, identifiers to export) as a brief; one `haiku` agent runs the script; one reviewer one tier up checks the diff against the brief.
- **FR-015**: Each PR MUST update the module's `specs.md` paths, `docs/agent-architecture.md` and any `specs/` or docs path that names a moved file (excluding `specs/done_*` history), in the same PR.
- **FR-016**: Each PR MUST keep spec 023's mapping valid: `python3 hack/ci_scope.py verify-suites` (once 023 adds it) passes, and every path in `test/e2e/suite-components.json` and `ci_scope.py` `file_consumers` exists.
- **FR-017**: Commits are signed (`-s`), conventional (`refactor:`), with the `Co-Authored-By` trailer; PRs carry `type: refactor` and one `area:` label; PR bodies carry no attribution block or session link.

**Ceiling and enforcement**

- **FR-018**: Every production source file (Go and web) MUST end at 500 lines or fewer (OD-3). Exempt: generated files (`zz_generated.*`, `web/src/api/types.ts`, `operator/config/`), CRD `operator/api/v1alpha1/*_types.go`, and the e2e harness under `test/e2e/` (out of scope, owned by spec 029). This covers files outside the packages named above too: today `api/internal/audit/audit.go` 1,050, `capture-sidecar/internal/httpserver/handlers.go` 975, `agent/internal/mods/mods.go` 932, `api/cmd/main.go` 914, `i18n/cmd/i18n-check/main.go` 781, `api/internal/auth/oidc.go` 711, `agent/internal/rcon/battleye.go` 703, `agent/internal/files/rooted_linux.go` 603, `operator/cmd/main.go` 519, `agent/internal/players/players.go` 509, and web `lib/endpoints.ts` 1,046, `components/modules/BuildModuleDialog.tsx` 973, `components/CaptureWidget.tsx` 826, `components/server/ServerActionsCard.tsx` 658, `components/modules/SourceDialog.tsx` 573, and the dev codemod `web/scripts/i18n-migrate.ts` 1,195 (OD-11).
- **FR-019**: After the last move, `make lint` MUST run a layout check that enforces the folder shape (027 OD-5) and the 500-line ceiling for production files; test files are exempt (OD-4).

**Web types**

- **FR-020**: `web/src/types.ts` is not merged into the generated types; it is split by domain behind a re-exporting `types.ts`. `web/src/api/types.ts` is untouched (OD-5).

### Key Entities

- **Move list**: per PR, the table of source path → destination path, the identifiers exported because they cross a new package line, and the path references updated. Written by the scout, applied by the script, checked by the reviewer.
- **Parity report**: per PR, test names before/after, coverage per touched module before/after, generated-output diff (empty), rename stats.
- **Group**: a set of production files plus their tests that moves together into one sub-package or one `pages/<Screen>/` folder.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: No production source file outside the FR-018 exemptions is over 500 lines; today 34 Go and 17 web production files are.
- **SC-002**: `api/internal/handlers/` and `operator/internal/controller/` hold no resource code at their root; each resource group is its own package (today one package each, 146 and 150 files).
- **SC-003**: Every service module in 027 OD-3 has a thin `cmd/main.go` and no logic files at its root.
- **SC-004**: Every screen lives under `web/src/pages/`, none over 500 lines, and `routes/` holds no screen code.
- **SC-005**: Over the whole spec, the test-name list on master after the last PR equals the list before the first PR plus any tests other work added meanwhile; zero tests lost.
- **SC-006**: Every coverage minimum holds on every merged PR's full run.
- **SC-007**: Zero user-visible or API-visible changes: OpenAPI, CRDs, RBAC, chart output and visual-diff screenshots are identical across the whole spec.
- **SC-008**: Each PR is reviewable as a move: at least 90% of its changed lines are in files git reports as renames or as pure declaration moves.

## Out of scope

- Any behaviour, API, CRD, chart or UI change, and any new feature.
- Rewriting logic, removing dead code, renaming for taste, or changing test assertions.
- The layout rules themselves (spec 027) and `docs/layout.md` (027's implementation PR).
- CI selection (spec 023) and e2e speed (spec 029).
- `test/e2e/` file sizes (`gameserver_e2e_test.go` 1,882 lines and others): the e2e harness is one package by design and spec 029 owns its changes.
- The `modules/` and `website/` submodules.

## Assumptions

- Spec 027's layout decisions stand as recorded on 2026-10-20; if 027 changes them, this spec follows.
- The audit-fix PRs (#712–#731) keep landing while this spec runs; move PRs are scheduled around open PRs rather than the other way round.
- Spec 023 PR 1 (#752) and the `ci: full-run` label exist; if 023's later PRs land midway, FR-016 covers its new files.
- No new e2e test (OD-10, constitution I exemption): nothing user-facing changes, and the full existing e2e suite on every PR is the proof.
